# Notes for AI coding agents working on Glint

Glint is a security scanner, so the code must stay safe to run on hostile input.

## Ground rules

- Python 3.11+, standard library only at runtime. Do not add dependencies.
- Run `python -m unittest discover -s tests -t .`, `ruff check .`, `ruff format --check .` and
  `mypy glint tests` before proposing a change.
- Every rule lives in its own module under `glint/rules/` with one `Rule` subclass, tests that
  must flag and must not flag, a card in `glint/cards/` and a section in `docs/rules.md`.
- Pass all evidence through `glint.textutil.safe()`. Never print a full secret.
- Write invisible characters as `\u` escapes in source files, never as raw characters.
- Compile regexes once at module level and keep repeats bounded (`.{0,80}`, not `.*`).

## Layout

- `glint/collector.py` finds agent files, `glint/parser.py` loads them.
- `glint/rules/` holds the checks; `glint/scanner.py` runs them.
- `glint/reporters/` turns results into terminal, JSON, SARIF or HTML output.
- `glint/gui.py` is the tkinter desktop app; its display logic lives in `glint/gui_model.py` so it can be
  tested without a display. Run `xvfb-run -a python -m unittest tests.test_gui` to test the window on Linux.
- `demo/` is generated by `scripts/make_demos.py`; edit the script, not the files.
